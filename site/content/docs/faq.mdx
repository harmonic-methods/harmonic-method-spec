# Frequently Asked Questions

<p className="cajon-page-lead">Questions about the Harmonic Method, how it works, and how its concepts apply in practice.</p>

<ul className="cajon-faq-list" aria-label="Harmonic Methods questions">

  <li className="cajon-faq-item">
    <div className="cajon-faq-question">What is AI-native software delivery?</div>
    <div className="cajon-faq-answer">
      <p><a href="/docs/ai-coding-agents">AI-native software delivery</a> is an approach to building software where AI coding agents perform most execution — writing, testing, and revising code — against an explicit, structured representation of intent, while people own the destination, tradeoffs, and review.</p>
      <p>Its defining constraint is no longer how fast code can be written, but how reliably intent and context can be expressed in a form agents can reason about. Harmonic Methods is the delivery method built for that model.</p>
    </div>
  </li>

  <li className="cajon-faq-item">
    <div className="cajon-faq-question">How is this different from existing delivery approaches?</div>
    <div className="cajon-faq-answer">
      <p>Traditional and iterative delivery approaches tend to center on delivery cadence and task management, organizing work into time-boxed cycles, tracking completion of items, and measuring velocity through those items.</p>
      <p>Harmonic Composition centers on different concerns: system coherence, capability evolution, and preserving context across handoffs. The primary unit is not a task to be closed but a capability to be developed. The primary measure of progress is not throughput but alignment — between what the system can do, what it is becoming, and where it is headed.</p>
      <p>These are complementary concerns. Harmonic Composition does not prescribe how a team should organize its time or meetings. It addresses what gets lost between those events: the reasoning, the capability definitions, and the destination.</p>
    </div>
  </li>

  <li className="cajon-faq-item">
    <div className="cajon-faq-question">How does this help with AI agents?</div>
    <div className="cajon-faq-answer">
      <p>AI agents execute well when context is explicit and the destination is clear. When the <a href="/docs/composition/key-concepts#coda">Coda</a> is defined, <a href="/docs/composition/key-concepts#notes">Notes</a> capture assumptions and constraints, and <a href="/docs/composition/key-concepts#beats">Beats</a> describe durable capabilities, agents have the structured context they need to operate reliably instead of guessing at intent.</p>
      <p>Without that structure, agents fill the gaps themselves. The gaps get filled quickly, but not necessarily correctly. Harmonic Composition was designed in part to address exactly this: the faster agents can execute, the more important it becomes to give them something accurate to execute against.</p>
    </div>
  </li>

  <li className="cajon-faq-item">
    <div className="cajon-faq-question">How do the functions relate to each other?</div>
    <div className="cajon-faq-answer">
      <p>The Harmonic Method's functions are scoped by altitude. <a href="/docs/composition">Composition</a> is where the Composer function defines intent within a single system or engagement. Orchestration is where the Orchestrator and Conductor functions coordinate delivery across multiple systems and agents. Portfolio Management is where the Producer function operates at the portfolio level, mapping capabilities across the wider landscape.</p>
      <p>They are designed to compose: Orchestration assumes Composition is running within each system; Portfolio Management provides the strategic context that individual Codas should reflect. You can start with Composition alone and layer in the others as the scope of your work expands.</p>
    </div>
  </li>

</ul>

## Composition

<hr />

<ul className="cajon-faq-list" aria-label="Composition questions">

  <li className="cajon-faq-item">
    <div className="cajon-faq-question">What happens to old Beats?</div>
    <div className="cajon-faq-answer">
      <p><a href="/docs/composition/key-concepts#beats">Beats</a> are durable by definition. A Beat remains in the system and continues to evolve through Revisions for as long as the capability it describes is relevant to the current <a href="/docs/composition/key-concepts#coda">Coda</a>.</p>
      <p>When a capability is no longer relevant — because the Coda has changed, the system has moved on, or the need no longer exists — the Beat can be retired. A retired Beat is not deleted. It becomes part of the record of what the system was and what it needed at a prior stage, which is itself a form of context worth preserving.</p>
    </div>
  </li>

  <li className="cajon-faq-item">
    <div className="cajon-faq-question">How does the Coda relate to Beats?</div>
    <div className="cajon-faq-answer">
      <p>The <a href="/docs/composition/key-concepts#coda">Coda</a> defines the destination; <a href="/docs/composition/key-concepts#beats">Beats</a> define the durable capabilities the system needs to reach it. The relationship is directional: the Coda shapes which Beats are relevant for a given phase, and the Beats collectively describe the path to the Coda.</p>
      <p>A Beat that cannot be connected to the current Coda does not belong in the current work. Conversely, a Coda that has no Beat supporting a critical capability it requires signals that the Beat set is incomplete. During <a href="/docs/composition/quality-gates">quality evaluation</a>, the relationship between the Coda and the Beats is explicitly assessed — not just whether each Beat is well-formed, but whether the full set of Beats is sufficient to reach the destination.</p>
    </div>
  </li>

  <li className="cajon-faq-item">
    <div className="cajon-faq-question">What is the role of Notes in execution?</div>
    <div className="cajon-faq-answer">
      <p><a href="/docs/composition/key-concepts#notes">Notes</a> carry the context — assumptions, constraints, and decisions — that keeps Revisions aligned with intent even as the team changes or time passes.</p>
      <p>During delivery, Notes serve as the reference layer: when a decision in a Revision is unclear, or when a constraint makes a straightforward approach unworkable, Notes provide the explanation. They transform institutional memory from something that lives in people's heads into something that lives in the system, available to whoever needs it, whenever they need it.</p>
    </div>
  </li>

</ul>
