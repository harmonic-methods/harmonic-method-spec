## The six roles [#functions]

<ul className="cajon-glossary-list">
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">Director</span><span className="cajon-glossary-def">The role accountable for strategic direction and whether its assumptions still hold. <a href="/docs/method/roles#director">Learn more →</a></span></li>
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">Composer</span><span className="cajon-glossary-def">The function that establishes intent. Defines what must become true and why, and the constraints that bound it. Owns the Coda, the Beats, and the Notes that explain them. <a href="/docs/method/roles#composer">Learn more →</a></span></li>
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">Conductor</span><span className="cajon-glossary-def">The function that holds coherence during execution. Applies real-time judgment when reality diverges from the plan, detects drift, and reanchors the work to intent. Continuous, not episodic. <a href="/docs/method/roles#conductor">Learn more →</a></span></li>
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">Orchestrator</span><span className="cajon-glossary-def">The function that turns intent into structure: sequencing, dependencies, and assignment of performers across humans and agents alike. <a href="/docs/method/roles#orchestrator">Learn more →</a></span></li>
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">Producer</span><span className="cajon-glossary-def">The function that owns value. Decides whether the work earns its keep — what gets funded, and what gets made. An implementation may supplement that decision with measures such as Value Velocity. <a href="/docs/method/value">Learn more →</a></span></li>
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">Promoter</span><span className="cajon-glossary-def">The function that carries the work to its audience. Owns whether the work is known, understood, and taken up by the people it was made for. <a href="/docs/method/roles#promoter">Learn more →</a></span></li>
      </ul>

## Primitives [#primitives]

<ul className="cajon-glossary-list">
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">Beat</span><span className="cajon-glossary-def">A durable, outcome-oriented capability the system must possess. Describes what a system must be able to do, not what must be built by a date. Its status is open or closed. <a href="/docs/method/primitives#beat">Learn more →</a></span></li>
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">Beat Version</span><span className="cajon-glossary-def">The planning increment — a planned slice of a Beat’s capability, carrying description, scope, and acceptance criteria. Answers "what are we trying to accomplish?" <a href="/docs/method/primitives#beat-versions">Learn more →</a></span></li>
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">Coda</span><span className="cajon-glossary-def">The resolved outcome an entity serves. A change to the Coda preserves the prior statement and its decision lineage. <a href="/docs/method/primitives#coda">Learn more →</a></span></li>
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">Coda drift</span><span className="cajon-glossary-def">Modulation without a new destination — the Notes in effect shifted key while the Coda stayed written in the old one. Nothing abandoned, nothing decided. <a href="/docs/method/listening#signals">Learn more →</a></span></li>
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">Note</span><span className="cajon-glossary-def">Explicit, versioned, discoverable context preserving the reasoning behind the work. Types: Background, Constraint, Guidance, and Decision. A Note is attached to the entity it informs. <a href="/docs/method/primitives#note">Learn more →</a></span></li>
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">Orphan Revision</span><span className="cajon-glossary-def">A hotfix or small operational fix that skips the Beat Version entirely and carries its own description. <a href="/docs/method/primitives#beat-versions">Learn more →</a></span></li>
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">Revision</span><span className="cajon-glossary-def">A tracked change that executes part or all of a Beat Version. It can be a pull request, procedure update, or another change artifact. <a href="/docs/method/primitives#beat-versions">Learn more →</a></span></li>
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">System</span><span className="cajon-glossary-def">The score — the whole composition, and the only level at which the work is heard as a piece. Evaluated for distinctiveness and coherence exactly as a Beat would be. <a href="/docs/method/metaphor#mapping">Learn more →</a></span></li>
      </ul>

## Quality model [#quality]

<ul className="cajon-glossary-list">
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">Clear</span><span className="cajon-glossary-def">One of the seven quality dimensions. Intent and scope are unambiguous, understandable without additional explanation. <a href="/docs/method/quality#dimensions">See all dimensions →</a></span></li>
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">Compose</span><span className="cajon-glossary-def">The second phase. Each Beat is evaluated against the seven dimensions, and the set examined for collective coherence. <a href="/docs/method/quality#phases">Learn more →</a></span></li>
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">Distinctive</span><span className="cajon-glossary-def">One of the seven quality dimensions. The capability stands apart from others without unnecessary overlap or duplication. <a href="/docs/method/quality#dimensions">See all dimensions →</a></span></li>
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">Durable</span><span className="cajon-glossary-def">One of the seven quality dimensions. Expected to remain relevant through the current phase and beyond, not obsolete once the first Revision ships. <a href="/docs/method/quality#dimensions">See all dimensions →</a></span></li>
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">Execute</span><span className="cajon-glossary-def">The third phase. Beat Versions are planned and Revisions delivered; the system moves toward the Coda increment by increment. <a href="/docs/method/quality#phases">Learn more →</a></span></li>
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">Explore</span><span className="cajon-glossary-def">The first phase. The Coda is defined, initial Beats identified, and Notes captured to establish the reasoning behind both. <a href="/docs/method/quality#phases">Learn more →</a></span></li>
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">Harmonious</span><span className="cajon-glossary-def">One of the seven quality dimensions, and the one requiring a vertical read. Integrates cleanly with the other Beats and supports, rather than conflicts with, the Coda. <a href="/docs/method/quality#dimensions">See all dimensions →</a></span></li>
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">Strategically Aligned</span><span className="cajon-glossary-def">One of the seven quality dimensions. Advances the system toward the Coda and reflects the priorities of the current phase. <a href="/docs/method/quality#dimensions">See all dimensions →</a></span></li>
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">Substantial</span><span className="cajon-glossary-def">One of the seven quality dimensions. A capability of genuine, lasting significance, not an implementation detail dressed as a capability. <a href="/docs/method/quality#dimensions">See all dimensions →</a></span></li>
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">Outcome-Oriented</span><span className="cajon-glossary-def">Names a result that survives a change in how it is achieved. <a href="/docs/method/quality#dimensions">See all dimensions →</a></span></li>
      </ul>

## Delivery structure [#delivery]

<ul className="cajon-glossary-list">
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">Deliverable</span><span className="cajon-glossary-def">A tangible artifact or milestone handed over to a client — a presentation, a report, a training session. Distinct from a Beat, which is a capability the product provides. <a href="/docs/method/delivery#deliverables">Learn more →</a></span></li>
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">Drop</span><span className="cajon-glossary-def">A release milestone: a named grouping of Beat Versions that ship together toward a client-visible outcome. Readiness is computed, not declared. <a href="/docs/method/delivery#drop">Learn more →</a></span></li>
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">Movement</span><span className="cajon-glossary-def">The commercial container — the engagement itself, a client SOW or contract. Distinct from any particular system or codebase. <a href="/docs/method/delivery#movement">Learn more →</a></span></li>
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">Track</span><span className="cajon-glossary-def">A named grouping of commitments within a Movement, grouped the way the engagement is sold and reported rather than the way it is built. <a href="/docs/method/delivery#track">Learn more →</a></span></li>
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">Work Item</span><span className="cajon-glossary-def">The atomic unit of planned work within a Track. May optionally point at a single Beat Version when the work is a software capability. <a href="/docs/method/delivery#work-item">Learn more →</a></span></li>
      </ul>

## Coordination and cadence [#coordination]

<ul className="cajon-glossary-list">
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">Assignment</span><span className="cajon-glossary-def">Durable ownership — who is responsible, however long it takes. A question about accountability rather than activity. <a href="/docs/method/coordination#assignment">Learn more →</a></span></li>
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">Bar</span><span className="cajon-glossary-def">The recurring planning window a team delivers within — the base tempo everything else is expressed in multiples of. <a href="/docs/method/cadence#bar">Learn more →</a></span></li>
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">Cadence Config</span><span className="cajon-glossary-def">The tunable tempo for a given client: how long a Bar runs, how many Bars between Downbeats, and how often a lighter read of progress lands in between. <a href="/docs/method/cadence#config">Learn more →</a></span></li>
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">Claim</span><span className="cajon-glossary-def">Who has the stand right now. Heartbeat-backed and auto-released when stale, so concurrent actors see work is taken before duplicating it. <a href="/docs/method/coordination#claim">Learn more →</a></span></li>
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">Downbeat</span><span className="cajon-glossary-def">The recalibration anchor — an honest, frozen reading of where work stands against its destination, set at a Bar boundary. Additive and non-destructive. <a href="/docs/method/cadence#downbeat">Learn more →</a></span></li>
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">Forces</span><span className="cajon-glossary-def">The performers available, human and AI. Not interchangeable, and the difference is not skill but failure mode. <a href="/docs/method/coordination#forces">Learn more →</a></span></li>
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">Handoff</span><span className="cajon-glossary-def">Passing work between agents, or between an agent and a human, without losing the context that explains why it looks the way it does. <a href="/docs/method/coordination#handoff">Learn more →</a></span></li>
        <li className="cajon-glossary-entry"><span className="cajon-glossary-term">Layer</span><span className="cajon-glossary-def">The section of the orchestra — parts grouped by architectural role rather than technology. <a href="/docs/method/metaphor#mapping">Learn more →</a></span></li>
      </ul>
