title: Define a Beat
description: Name one lasting capability that supports the outcome.
---

A [Beat](/docs/method/primitives#beat) is a capability the System needs. A Beat has its own Coda that serves the System Coda you just drafted.

## Draft one capability

1. **Pick one part of the System Coda.** Ask what the System has to be able to do repeatedly for that outcome to hold.
2. **Name the capability.** Use a title that will still make sense if the team changes how it builds or operates the capability.
3. **Write the Beat Coda and a short description.** Say what will be true, who benefits, and what belongs inside this capability.
4. **Check it against the other Beats.** Look for overlapping promises and ask whether any part of the System Coda is still uncovered.

## Worked example

**Title**

Estimate approval status

**Beat Coda**

Account leads can see the current approval state on the estimate record before deciding whether to send it.

**Description**

The estimate record shows whether approval is pending, granted, or declined. It reflects the designated approver's decision when one is recorded.

Use the System Coda from the previous page as this Beat Coda's parent. Next, [run a Coda check](/docs/getting-started/run-a-coda-check) on the Beat.
