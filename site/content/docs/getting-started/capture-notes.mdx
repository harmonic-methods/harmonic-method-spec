---
title: Capture Notes
description: Record the facts, boundaries, and decisions that shape the work.
---

Start with one real piece of work. In this walkthrough, a team wants to reduce delays in approving client estimates. You can follow along in a document or use the steps on an initiative of your own.

## Write your first Notes

1. **Record what you know.** Start with a fact or an assumption that affects the work. Mark assumptions as unconfirmed and say how you could check them.
2. **Capture any boundaries.** Write down requirements the team must respect. Use a guidance Note for advice about how to approach the work.
3. **Record choices and why you made them.** Give each decision its own Note with its rationale.
4. **Keep each Note with the work it informs.** Start with the System for context that affects the whole initiative. Attach narrower Notes to the relevant Beat once it exists.

## Worked example

| Type | Note |
| --- | --- |
| Background | In a review of recent estimates, account leads had to ask for approval status in chat. |
| Constraint | Only the designated approver may approve an estimate. |
| Guidance | Use the same status names in the estimate record and in messages to account leads. |
| Decision | Start with one team so we can see where the approval process stalls before expanding it. |

Add a source when it will help a reader verify a claim. If a shared Note changes in substance later, record a new Note that supersedes it so readers can trace the change.
