## Try the open spec kit [#starter-kit]

The starter kit is pending public release. If you have a preview ZIP, unzip it and open `START_HERE.md`. The worked example takes you through a proposed capability and returns a score for each dimension, an overall verdict, and one practical improvement.

Use your organization's approved AI workspace and files it permits you to process there. That workspace may process file contents in the cloud.

### Review one document in chat

1. Attach `review-a-capability.md` and `sample-capability.md` to a new chat.
2. Paste the prompt below. To review your own work, attach your document in place of the sample. Include the broader outcome it serves if you have it.

> Follow the Harmonic Method rubric in review-a-capability.md to assess the proposed capability in the other attachment. Cite the document in your reasons and recommend the single most useful improvement. Flag missing context instead of making it up.

### Work with a local folder

1. Open the extracted folder in your approved desktop AI app and grant it access to the folder.
2. Paste the prompt below. To review your own work, put copies in `your-files/` and name the document you want reviewed.

> Read skills/coda-quality-check/SKILL.md and follow it to review the capability in sample-capability.md. Read the referenced specs, report the rubric's results, and recommend the single most useful improvement. Leave the source files as they are.

Use the chat option if your approved app supports attachments but cannot open a local folder. Decisions and approvals stay with the people responsible for the work.

## The pathway [#steps]

<ol className="cajon-steps-list">
        <li className="cajon-step-item">
          <span className="cajon-step-num">1</span>
          <div className="cajon-step-body">
            <strong>Capture initial Notes</strong>
            <p>Record the assumptions, constraints, guidance, and decisions you already know. <a href="/docs/method/primitives#note">Notes</a> at this stage document the context that shapes everything downstream: what the team knows about the problem space, what boundaries must be respected, and what is being taken as given. They are not expected to be complete.</p>
          </div>
        </li>
        <li className="cajon-step-item">
          <span className="cajon-step-num">2</span>
          <div className="cajon-step-body">
            <strong>Define the Coda</strong>
            <p>Articulate the specific, resolved end-state the system converges toward for this phase. The <a href="/docs/method/primitives#coda">Coda</a> describes a concrete state, not an aspiration. If multiple stakeholders are involved, surface disagreement here — misaligned Codas are far more costly to resolve in Execute.</p>
          </div>
        </li>
        <li className="cajon-step-item">
          <span className="cajon-step-num">3</span>
          <div className="cajon-step-body">
            <strong>Identify the Beats</strong>
            <p>Define the durable capabilities the system must possess to reach the Coda. Each <a href="/docs/method/primitives#beat">Beat</a> describes what the system must be able to do, not what must be built by a date. Aim for a set that covers what the Coda requires without significant overlap.</p>
          </div>
        </li>
        <li className="cajon-step-item">
          <span className="cajon-step-num">4</span>
          <div className="cajon-step-body">
            <strong>Apply the quality dimensions</strong>
            <p>Evaluate each Beat against the <a href="/docs/method/quality#dimensions">seven dimensions</a>: Distinctive, Harmonious, Substantial, Durable, Clear, Strategically Aligned, and Outcome-Oriented. Then evaluate the set: do the Beats collectively support the Coda, and is any required capability missing?</p>
          </div>
        </li>
        <li className="cajon-step-item">
          <span className="cajon-step-num">5</span>
          <div className="cajon-step-body">
            <strong>Plan Beat Versions and deliver Revisions</strong>
            <p>Each Beat advances through <a href="/docs/method/primitives#beat-versions">Beat Versions</a> — planned increments carrying description, scope, and acceptance criteria — delivered by one or more Revisions. The system moves toward the Coda increment by increment, and Notes continue accumulating.</p>
          </div>
        </li>
      </ol>

<div className="cajon-callout">The time invested in steps 1 to 4 is not overhead. It is the work that makes step 5 coherent. Teams that skip Explore and Compose typically rebuild the same context later, at higher cost, under more pressure.</div>

## Check which function is unowned [#functions]

<p>Before starting, name who holds each of the <a href="/docs/method/roles">five functions</a> for this work. They are functions, not headcount — one person may hold three. The diagnostic question is not who has the title, but whether the function is owned at all.</p>
