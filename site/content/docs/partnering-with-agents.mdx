# Partnering with AI Agents

<p className="cajon-page-lead">The question most teams are asking about AI is how fast it can go. The more important question is how to ensure it goes in the right direction — and what becomes possible when it does.</p>

## The context problem at AI speeds

Context has always degraded across handoffs. As work moves from conversation to document to ticket to code review and back again, the reasoning behind decisions gets lost. Teams rebuilt it continuously — from documentation, from memory, from institutional knowledge that lived in a few people's heads. The waste was real but slow enough to absorb.

AI changes the math. An agent executing without context doesn't work slowly in the wrong direction — it works fast. The faster the execution, the more expensive the missing context becomes. Every team that has tried to accelerate delivery with AI eventually discovers this: speed is easy. Direction is hard.

The answer is not to slow down. It is to structure context so agents can reason about it rather than guess at it. This is the core discipline of building with <a href="/docs/ai-coding-agents">AI coding agents</a> — where agents handle execution and the delivery method's job is to supply intent they can act on.

---

## What structured context actually enables

There is a meaningful difference between context that agents can *read* and context that agents can *reason about systematically*.

Documents and tickets give agents words. An agent reading an epic or a Jira ticket can summarize it, reference it, and act on explicit instructions. But it cannot reason about how that item relates to fifty others, whether it overlaps with existing capabilities, or whether it conflicts with a decision made six months ago.

[Beats](/docs/composition/beats), [Notes](/docs/composition/notes), and a [Coda](/docs/composition/coda) give agents concepts. When capabilities are defined as Beats — durable, outcome-oriented, non-overlapping — and decisions are captured as Notes with explicit types and anchored reasoning, and the destination is stated as a Coda, agents have something they can reason against. Not just read.

This distinction is the foundation of everything that follows.

## What the partnership looks like in practice

Partnering with agents in this model is not "give the agent a task and check the output." It is a structured division of work built on each party's actual strengths.

The loop looks like this: people define the destination and identify initial capabilities as Beats. Agents evaluate them for quality, surface overlap, and map interactions across the full corpus. People review findings and make judgment calls. Agents execute Revisions against well-defined [Beat Versions](/docs/composition/key-concepts#beat-versions). Each Revision adds to the corpus; each addition makes future agent reasoning more accurate.

Neither is doing the other's job. The corpus grows richer over time, and the partnership gets stronger as it does.

## How the discipline gets absorbed

The most common objection to methodology formalism — Notes to file, quality gates to pass, Revision IDs to track — is that it costs human time to maintain. In Scrum, ceremonies are forcing functions: the standup happens daily whether the team wants it or not. Someone is accountable for the backlog because the framework names them. The discipline is enforced by the process.

Harmonic Composition works differently. The discipline overhead is absorbed by the agent, not the team.

**An implementation can automate accountability checks.** A tool may check that a change serves an active plan before an agent edits a file. This repository does not install such a hook. In a Git-hosted workflow, the pull request can be the Revision; the method does not require a separate pre-existing Revision record.

**Notes get filed by the agent, not because a human remembered.** When a decision is made, a constraint surfaces, or context matters to future reasoning, the agent files the Note as part of the turn. The corpus grows with every session because accumulating context is part of what the agent does — not an optional documentation step layered on top of the work.

**Agents can assist with quality evaluation.** The published rubrics assess seven Coda quality dimensions and six plan quality dimensions per Beat Version. An agent can return scores, reasons and improvement guidance. Review the evidence behind the assessment; completion time and reliability depend on the agent and inputs, and enforcement belongs to the implementation.

The result is a methodology that is more rigorous than most backlog-driven processes but less demanding on human time. The formalism that makes Harmonic Composition effective is largely invisible to the team because the agent handles it. Humans provide the judgment that no agent can supply — the Coda, the tradeoffs, the domain authority. Agents handle the mechanical compliance that no human team maintains consistently.

## Super-human product management

This is where the capability becomes genuinely new.

A human PM working with a product corpus can hold roughly twenty or thirty capabilities in working memory at once. They develop intuitions about the system over time, but those intuitions are personal, opaque, and leave when they do. At a certain scale — fifty Beats, a hundred, more — the system becomes too large for any individual to reason about with precision.

An agent working with a well-structured Harmonic corpus holds all of it simultaneously.

When a new capability is proposed, an agent with access to the full Beat set can:

## The precondition

All of this depends on the corpus being structured in a way agents can reason about. The capability above does not exist when work is tracked in epics, stories, and Jira tickets — because those primitives were designed to manage scope, not to represent a system's capability space in a form that supports systematic reasoning.

Epics give agents words. [Beats](/docs/composition/beats) give agents concepts.

[Notes](/docs/composition/notes) give agents the reasoning behind decisions, not just the decisions themselves. A constraint Note does not just record that something is off-limits — it records why, so agents can determine whether that constraint still applies in a new context.

A [Coda](/docs/composition/coda) gives every evaluation a reference point. Overlap, interaction, fit — all of these are relative to where the system is headed. Without a stated destination, no agent can assess whether a proposed capability actually belongs.

Harmonic Methods is the structure that makes the partnership possible. The Beats define the capability space. The Notes preserve the reasoning. The Coda gives every evaluation a reference point. Together, they give agents something worth working with — and something that grows more valuable with every Revision that ships.
